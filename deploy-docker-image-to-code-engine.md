# 🐳 Deploying Your First Docker Image on IBM Cloud Code Engine Using Python

## 📌 Lab Overview

**Platform:** IBM Cloud Code Engine  
**Language:** Python  
**Framework:** Flask  
**Containerisation:** Docker  
**Estimated Time:** 20 minutes

In this lab, you will build a Docker image for a Python Flask application, push the image to IBM Cloud Container Registry, and deploy the application using IBM Cloud Code Engine.

The deployed application exposes a REST API endpoint at the root URL (`/`) that returns a simple **Hello World** message.

---

## 🎯 Learning Objectives

By completing this lab, you will learn how to:

- Start the IBM Cloud Code Engine service.
- Create a Code Engine project.
- List existing deployed applications.
- Clone a Python Flask application from GitHub.
- Build and tag a Docker image.
- Push a Docker image to IBM Cloud Container Registry.
- Deploy a containerised application to Code Engine.
- Access the deployed application through a public URL.
- Update an existing application after modifying its source code.

---

## 🛠️ Prerequisites

Before starting, ensure that you have access to the lab environment with the following tools and configurations:

- IBM Cloud Code Engine.
- Code Engine CLI.
- Docker.
- Git.
- A configured IBM Cloud Container Registry namespace.
- A preconfigured registry secret named `icr-secret`.

The lab environment prepares the CLI, project and Kubernetes configuration for you.

---

## ☁️ Part 1: Set Up IBM Cloud Code Engine

1. Open the lab environment.
2. Navigate to the **Cloud** dropdown menu.
3. Select **Code Engine**.
4. Click **Create Project**.
5. Wait for the environment setup to complete.
6. Once Code Engine is active, open **Code Engine CLI** to launch the preconfigured terminal.

The terminal should open in the current working directory with the project and Kubernetes configuration already set up.

---

## 📋 Part 2: List Existing Applications

Use the following command to display the applications currently deployed in your Code Engine project.

"```
ibmcloud ce app list
```"

This helps you identify existing applications and avoid naming conflicts.

---

## 📥 Part 3: Clone the Python Flask Application

Clone the lab's GitHub repository.

"```
git clone https://github.com/ibm-developer-skills-network/danum-pythonflaskserver
```"

Navigate to the cloned project directory.

"```
cd danum-pythonflaskserver
```"

The repository contains the Python Flask application that will be packaged into a Docker image.

---

## 🐳 Part 4: Build the Docker Image

Build the Docker image and tag it with the IBM Cloud Container Registry namespace provided by the lab environment.

"```
docker build . -t us.icr.io/${SN_ICR_NAMESPACE}/helloworld2
```"

### Understanding the command

| Component | Description |
|---|---|
| `docker build .` | Builds an image using the Dockerfile in the current directory. |
| `-t` | Assigns a name and tag to the image. |
| `us.icr.io` | IBM Cloud Container Registry endpoint used by the lab. |
| `${SN_ICR_NAMESPACE}` | Environment variable containing the registry namespace. |
| `helloworld2` | Name assigned to the Docker image. |

**Note:** The lab uses `helloworld2` because an earlier `helloworld` application may already exist in the project.

---

## 📤 Part 5: Push the Docker Image to IBM Cloud Container Registry

Upload the built image to the registry so Code Engine can access it.

"```
docker push us.icr.io/${SN_ICR_NAMESPACE}/helloworld2
```"

Once the push completes successfully, the image is available in the registry namespace.

---

## 🚀 Part 6: Deploy the Application

Create the Code Engine application using the Docker image you just pushed.

"```
ibmcloud ce application create --name helloworld2 --image us.icr.io/${SN_ICR_NAMESPACE}/helloworld2 --registry-secret icr-secret --port 5000
```"

### Understanding the command

| Option | Purpose |
|---|---|
| `application create` | Creates a new Code Engine application. |
| `--name helloworld2` | Sets the application name. |
| `--image` | Specifies the Docker image to deploy. |
| `--registry-secret icr-secret` | Specifies the registry secret used to access the image. |
| `--port 5000` | Configures the application to receive traffic on port 5000. |

Code Engine creates the application and provisions the infrastructure needed to run it.

After deployment, the CLI displays a URL for accessing the application.

**Important:** The image is built and pushed before deployment, so the create command does not need to specify a source-code build configuration.

---

## 🌐 Part 7: Test the Deployed Application

1. Copy the URL generated by the deployment command.
2. Open the URL in your browser.
3. Verify that the application displays the Hello World response.

The application serves its response through the root endpoint (`/`).

### Expected result

"```
Hello World
```"

If the application responds successfully, your first Dockerised Python application has been deployed to IBM Cloud Code Engine.

---

## 🧪 Part 8: Practice Exercise — Update the Application

In this exercise, you will change the application's response and redeploy the updated Docker image.

### Step 1: Modify the Python application

Open the following file in the lab's file editor:

"```
danum-pythonflaskserver/app.py
```"

Find the existing message:

"```
Hello World
```"

Change it to:

"```
Hello yourname!
```"

Replace `yourname` with your preferred name.

Save the file.

### Step 2: Rebuild the Docker image

Since the application source code has changed, rebuild the image using the same name and tag.

"```
docker build . -t us.icr.io/${SN_ICR_NAMESPACE}/helloworld2
```"

### Step 3: Push the updated image

Push the rebuilt image to the registry.

"```
docker push us.icr.io/${SN_ICR_NAMESPACE}/helloworld2
```"

### Step 4: Update the existing Code Engine application

Run the following command to update the application with the rebuilt image.

"```
ibmcloud ce application update --name helloworld2 --image us.icr.io/${SN_ICR_NAMESPACE}/helloworld2 --registry-secret icr-secret --port 5000
```"

This updates the existing application rather than creating a second application with the same name.

### Step 5: Verify the update

1. Wait for the update to complete.
2. Open the application URL again.
3. Confirm that the new message appears.

**Expected response:**

"```
Hello yourname!
```"

If the updated response does not appear immediately, check the deployment status and allow the new application revision to become ready before testing again.

## 🔑 Key Concepts Learned

| Concept | Description |
|---|---|
| Docker image | A packaged application and its required dependencies. |
| Docker build | Creates a container image from the project and its Dockerfile. |
| Container Registry | Stores container images so they can be retrieved for deployment. |
| Code Engine | Runs containerised applications on managed cloud infrastructure. |
| Registry secret | Provides the credentials needed to access a private image registry. |
| Application deployment | Makes the packaged application available to run in the cloud. |
| Application URL | Provides an endpoint through which users can access the deployed application. |
| Application update | Deploys a new image version to an existing application. |

## ⚠️ Troubleshooting Notes

- **Application name conflict:** Check existing applications before creating a new one. This lab uses `helloworld2` to avoid a possible conflict.
- **Image push failure:** Verify that the registry namespace and authentication are configured correctly.
- **Image pull failure:** Confirm that the `icr-secret` registry secret is available and has the required access.
- **Application not responding:** Verify that the application listens on port `5000` and that deployment has completed successfully.
- **Old response still appears:** Confirm that you rebuilt and pushed the image before running the application update command.
